歩くのが楽しくなるARアプリ

現実の街をゲームにする。
歩くことを楽しくし、安全をゲーム体験の中に組み込む。

1. プロジェクト概要
1.1 コンセプト

「歩くのが楽しくなるアプリ」

歩行者に「歩きスマホをやめさせる」のではなく、アプリ側が歩行という行動に合わせて変化する。

現実の街をARゲーム化し、

前を向いて歩く

周囲の環境を見る

信号や道路状況を確認する

安全に目的地まで歩く

といった行動そのものをゲーム体験にする。

1.2 基本思想

歩行者を変えるのではなく、アプリを変える。

従来の歩きスマホ対策では、ユーザーに「スマホを見るな」と要求する。

本アプリでは逆に、

「スマホを使いたい」というユーザーの行動を前提として、
スマホ側が安全な使い方に適応する。

1.3 最終的な目的

歩きスマホによる事故を減らしながら、

「歩くのが楽しい」

という体験を提供する。

事故防止をユーザーへの制限としてではなく、ゲームシステムとして実装する。

2. プロダクトコンセプト
2.1 キャッチコピー

歩けば、世界がゲームになる。

2.2 プロダクトの特徴

現実世界に存在するものをゲームイベントとして扱う。

例：

現実世界	ゲーム上の役割
信号	イベント
横断歩道	クエスト
公園	モンスター出現エリア
駅	ダンジョン
建物・名所	スポット
天気	ワールドイベント
歩行距離	経験値
目的地	ミッション
3. コアゲームシステム
3.1 ARゲーム

ユーザーが歩いていると、現実の風景にゲームオブジェクトが表示される。

例：

モンスター

アイテム

クエスト

宝箱

NPC

エフェクト

イベント

ゲームの進行は、現実世界の位置・環境・時間などによって変化する。

3.2 「前を見る」ことをゲームにする

ユーザーに「前を見てください」と警告するのではなく、

前を見ることでゲームをプレイできる

設計にする。

基本ルール
前方を見ている
    ↓
ARゲーム表示
    ↓
ゲームプレイ可能

下を向く
    ↓
ARゲーム停止 / 画面暗転
    ↓
安全確認

再び前方を向く
    ↓
ゲーム再開
4. 安全システム

安全機能は「ゲームを邪魔する機能」ではなく、ゲームそのもののルールとして実装する。

4.1 障害物検知

カメラなどを利用して前方の障害物を検知する。

対象例：

人

自転車

車

電柱

壁

柵

段差

その他の障害物

危険度が高いと判断された場合、

障害物検知
    ↓
危険度判定
    ↓
ゲーム表示停止
    ↓
必要に応じて画面暗転
    ↓
振動 / 音声で通知
4.2 下向き検知

端末の姿勢などから、ユーザーがスマートフォンを下向きにしている状態を検知する。

下向き
  ↓
AR表示停止

前方を向く
  ↓
AR表示復帰
目的

ユーザーに「画面を見ないで」と要求するのではなく、

「画面を見るためには前を向く必要がある」

というゲーム構造を作る。

5. 信号イベント

信号を単なる交通設備ではなく、ゲームイベントとして扱う。

5.1 赤信号

例：

イベント準備

ミニゲーム

NPCとの会話

アイテム生成

クエスト進行

ただし、赤信号待ちのユーザーを画面に釘付けにしないよう、安全を最優先する。

5.2 青信号

例：

イベント開始

クエスト進行

移動開始

報酬判定

信号が青になったことを検知した場合でも、ユーザーに「急いで渡る」ことを促す設計にはしない。

5.3 黄色・点滅

安全優先モード。

黄色 / 点滅
    ↓
ゲームイベント停止
    ↓
必要に応じて画面暗転
    ↓
周囲確認を優先
6. ゲームデザイン
6.1 歩行そのものをゲーム化

歩いた距離や発見した場所などをゲーム内の進行に利用する。

例：

歩行距離 → XP

新しい場所 → 発見ポイント

安全な歩行 → コンボ

クエスト達成 → アイテム

特定スポット到達 → 特別イベント

6.2 安全行動を報酬化

安全に歩くことを罰則ではなく報酬として扱う。

例：

安全に歩く
    ↓
コンボ継続
    ↓
XP獲得
    ↓
アイテム獲得
    ↓
キャラクター成長
6.3 重要なゲーム原則

ゲームに夢中になるほど危険になる設計は禁止する。

NG

画面を長時間見続けるほど有利

歩行速度を上げるほど有利

信号を無視すると高得点

危険な場所に行くほど高報酬

OK

周囲を確認するほど有利

安全に歩くほど有利

新しい場所を発見すると報酬

前を向いていることでゲームが継続

8. AR設計
8.1 ARの目的

ARは単にゲームオブジェクトを表示するためだけに使用するのではない。

現実世界を見ることそのものをゲームプレイにする。

8.2 AR UI原則

視界を大きく遮らない

現実の障害物を隠さない

重要情報を最小限にする

危険時にはAR表示を停止する

ユーザーが画面を凝視しなくても成立する設計を目指す

14. プライバシー

カメラや位置情報を利用するため、プライバシーを重要な設計項目とする。

原則：

必要以上の位置情報を保存しない

カメラ映像を不要にサーバーへ送信しない

可能な処理は端末上で行う

ユーザーにデータ利用目的を明示する

保存するデータを最小化する

15. プロダクトの成功条件

単純に「アプリを使った人数」だけでは評価しない。

重要な指標：

継続利用率

歩行時間

歩行距離

ゲームイベント発見数

ユーザー満足度

安全機能の発動回数

ユーザーが前方を確認できている時間

「歩くことが楽しくなった」と感じるユーザーの割合

16. プロダクト哲学

このアプリは、

歩きスマホを禁止するアプリではない。

歩きスマホを安全な体験へ再設計するアプリである。

ユーザーを教育するのではなく、
ユーザーに我慢させるのでもなく、
アプリ側が環境に適応する。

人間をアプリに合わせるのではなく、
アプリを人間に合わせる。

そして最終的な目的は、

「歩くのが楽しい」

と思ってもらうこと。

安全は、その体験の中に自然に組み込まれる。
